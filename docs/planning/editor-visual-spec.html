各屏说明与状态映射

画面语义与可达能力
V01 活动10月2日10:30–11:00 Gap草稿，两端approximate；标题是用户已输入的整理桌面。图中“草稿已保留”仅表示本样例写入成功；保存前不进入账本。选择Unknown不强制标题，不清已有内容。更正活动用同一结构、原源ID与“保存更正”。
V02 睡眠已有主睡眠更正，入睡约10月1日23:40、醒来准确10月2日07:20。完整约7小时40分，不是当日切片7小时20分。新建时显示“选择入睡时间/醒来时间”，不预置无依据值；备注有值展示摘要。
V03 复盘复盘10月2日，第一步意向10月3日；文字是演示输入。“再写几句”展开概述/反思并聚焦概述；修改日期走既有唯一性合同。主保存可只凭合法第一步完成。
V04 连续写作同一复盘展开概述/反思，正文已滚到概述附近；上一项回第一步，下一项进反思，反思上的附件显示完成。第一步摘要显示在顶部以保持上下文；不是新增独立页面。读事实后显式继续写作回原光标。
V05 时间编辑同一全屏可滚动编辑层展示两个完整日期端点及各自精度。点日期/时间调用既有可用选择器；手动输入保留。应用只改草稿，取消丢弃此次时间层未应用选择，正式保存另行发生。近似不因手动调整自动变准确。
V06 保存冲突活动结束改为11:15后与散步11:00–11:30冲突；保留输入、指出具体对象、提供修改时间。正常保存不能自动触发此示例。草稿写入失败、正式提交后清理失败分别使用下表动作，不混同。

非正常状态沿用同一布局

情况文案与动作
初次读取 / 原记录缺失加载不展示伪造字段值；读取失败有重试。源记录已不存在时不自动重建，按既有流程处理草稿与返回。
草稿写入中 / 失败保存条状态用“正在保留…”；失败用“草稿未保留”并在正文可见错误区提供重试，不能标已保留。显式保留返回沿用flush失败停留合同；更多仍可放弃草稿。
校验错误名称空：“写下这段时间做了什么，或选择想不起来”；第一步空：“写下一步要做的事”。定位字段并展开；不加常驻星号或“必填”标记。
正式提交中主动作显示“正在保存…”并禁止重复提交；不在列表提前显示新事实，不丢当前输入。
已提交但清理/重读失败明确“已保存，账本尚未更新”或“已保存，草稿清理未完成”，只读保留结果；主动作改为既有继续清理并刷新，返回路径按各表单合同，不再次正式提交。
删除 / 放弃更多菜单中清楚区分“放弃草稿”和既有正式记录删除；新建不显示删除。活动删除仍从详情进入，睡眠/复盘更正保留删除；原确认、失败和部分成功合同不变。

响应式与实施交接
