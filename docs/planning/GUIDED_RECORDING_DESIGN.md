## 已确认的决定

来自本次用户对话，追溯见 [Q-025 / Q-026](../domain/OPEN_QUESTIONS.md#q-025)。

- 常用目标由用户明确指定。新记录可预选该目标，每笔均能更换或取消关联；本笔修改不隐式改写常用目标设置。已有记录和恢复草稿以自身关联为准。

- 时间的完整调整路径可以不使用键盘。基础组件优先使用 Flutter 内置 Material 3。
- 节奏仍为推进 / 卡住 / 休息三个可见选择；“休息”承接 recovery 语义，不扩展为普通生活分类。不选任何一个表达无 annotation，无第四个节奏枚举。

领域语义以 [源提案](../../time-ledger-domain-model-v4-proposal.md)、[DOMAIN_RULES](../domain/DOMAIN_RULES.md)、[OPEN_QUESTIONS](../domain/OPEN_QUESTIONS.md) 为依据。新决定更新进入顺序和呈现方式，不改变 TimeBlock、RhythmAnnotation、SleepSession 的关系。未知、精度、重叠和草稿仍遵守既有合同。

## 共用界面骨架

顶部保留退出、步骤说明（1/3、2/3、3/3）和目标关联条；正文每幕只突出一个问题；底部提供上一步与继续 / 保存。步骤说明只是操作位置，不是每日完成度或打卡。

目标条示例：`关联目标：备考  [更换] [取消关联]`。它显示本笔实际关联，不能混淆成仅供展示的长期背景。取消后显示轻量的关联入口，不要求重新选目标。无目标、目标读取失败均不强制创建目标才可填写。

用户指定的常用目标只可作为新记录初值。原草稿和更正记录优先；目标已归档或已不可用时不新增该关联，不自动换成另一个目标；恢复方式遵守既有引用合同，进一步呈现需原型覆盖。无目标记录仍可选择任意节奏。

**2026-10-06补充（Q-025）：** 成功归档 / 删除常用目标后清除该常用选择，恢复Goal后也不自动重新设为常用，须用户手动设置；失败不声称清除成功。原草稿和更正记录仍以自身关联为准，不因偏好清除而自动解除原关联。本次是产品决定登记与原型验证，不表示正式偏好存储已实现。

三幕共用一份活动草稿。上一幕的答案在后续幕以可点击短摘要出现；点击修改后，继续回到原来的幕，而不是再走完全部后续步骤。默认不主动弹键盘。

## 第一幕：节奏

**主问题：** “这段时间，节奏怎么样？”

提供三个直接可见、单选且可取消的答案：

| 答案 | 一句语义提示 | 正式解释 |
| --- | --- | --- |
| 推进 | 确认这件事向前走了一点 | progress |
| 卡住 | 想推进，但遇到了阻力 | stuck |
| 休息 | 让自己缓一缓，能够继续 | recovery |

**推荐操作：** 选中后点“继续”。不选任何答案也能点“继续”；再次点击已选项取消。选择不自动跳页，用户可以比较答案、调整目标或取消选择；避免在还未确认时突然切屏。底部继续始终可用，无状态通过这条路径成立。

普通吃饭、工作、社交可以不选；不能因标题或目标自动判定节奏。夜间睡眠和小睡从独立睡眠入口记录，不塞进本页休息分支。

本幕不询问卡住原因、恢复方式、质量和下一步。

## 第二幕：事项

**主问题跟随已选答案，含义始终指向实际发生的事情：**

| 第一幕回答 | 第二幕主问题 | 可接受的短答案 |
| --- | --- | --- |
| 推进 | “这段推进了什么？” | 做完一套阅读题 |
| 卡住 | “刚才在做哪件事时卡住了？” | 理数据库的表关系 |
| 休息 | “这段怎么休息的？” | 出去散步 |
| 未选 | “这段主要做了什么？” | 吃午饭 |

问题提示不是原因调查，不把“原本打算做”替代为“实际做了”。只有这一处主要文字输入，几个字即可，不要求完整句子。

“想不起来”在输入旁直接可达；选择后无需活动名，仍保留先前文字、目标和节奏。知道卡住但记不清具体事项，可以保留 stuck 并选择 Unknown，不能强制清掉第一幕答案。

Known 必须有合法活动名。不得用目标名、节奏名称或系统猜测偷偷生成活动标题以绕过校验。切回“记得”时还原原文。

输入后继续进入时间幕。可点击的近期活动建议可以后续验证：仅由用户选择来填活动文字，不建立分类、不自动推断节奏；不是首轮必需组件。

## 第三幕：时间与提交

**主问题：** 有已选区间 / 合法建议时，“是这段时间吗？”；没有建议时，“这段是什么时候？”

显示开始、结束两张端点卡：各自日期、时分、当前精度；中间显示派生时长。日期和时分分别可点选，精度使用准确 / 大概的单选组件。时长由两端计算，不能再引入一个可能冲突的必填时长字段。

- 点击具体 Gap：沿用所选区间，不要求重新输入。
- 今天已有事实且有尾部 Gap：沿用 Q-023 的可修改建议。
- 历史日 / 没有尾部建议：在本幕选择候选 Gap，即使只有一个也由用户确认。
- 当天无事实、没有 Gap 或未来日期：两端未填，从可点选的日期和时钟开始，不默填午夜至当前时间。
- 切换问答幕不会重新生成建议覆盖已修改区间；系统建议在进入时按上下文计算，恢复草稿优先。

顶部摘要给出本笔目标、节奏和事项，各项可回去修改。第三幕就是最终确认，主按钮“保存记录”，不新增第四幕核对页。

合法保存后返回来源账本并定位该笔，提示已保存。保存失败留在本幕；冲突明确显示已有记录及区间，用户修改，不自动拆分、截断或覆盖。已写入但清草稿 / 刷新失败时重试收尾，不重新提交。

## 时间组件基线：完整触控路径

实现优先使用 Flutter 已提供的 Material 3 组件；项目 ThemeData 已设置 `useMaterial3: true`。

| 用途 | 组件 / 方式 | 本产品需要组合的职责 |
| --- | --- | --- |
| 选日 | `showDatePicker` 日历模式 | 为单个端点选择日期 |
| 选时分 | `showTimePicker` 时钟模式 | 为同一端点选择小时和分钟，采用24小时呈现 |
| 节奏选择 | `SegmentedButton` 允许空选择，或标准单选列表 | 三种答案的语义、无状态继续路径 |
| 目标选择 | 标准 Chip / ListTile 与底部面板 | 常用目标初值、替换和取消关联 |
| 活动输入 | `TextField` | 简短事实描述、记得 / 想不起来 |
| 精度 | `SegmentedButton` | 两端独立选择准确 / 大概 |
| 继续 / 保存 / 返回 | `FilledButton`、`TextButton`、`IconButton` | 逐幕导航、验证和提交 |
| 补充 / 校验反馈 | `BottomSheet` / 标准错误文本 | 临时编辑、应用与取消、错误恢复 |

不用键盘是整条路径的验收条件，不只是首次打开选时器采用表盘。日期、小时、分钟、跨日、精度均需能通过点击完成。手动输入可作为主动选择的辅助方式，不能成为必经步骤；也不能在大字或短窗口时自动改成只能打字。

官方 `dial` / `calendar` 模式带可选输入切换；如果原型要严格排除文本入口，可以分别使用 `TimePickerEntryMode.dialOnly`、`DatePickerEntryMode.calendarOnly`。组件内置交互优先，日期与时分的组合、双端顺序、跨日验证由产品容器负责。没有一个 picker 同时替我们解决完整日期时间区间。

未填端点时，选择器需要一个初始显示位置，但它不是已确认时间；只有明确选择 / 确认并应用后才回写草稿，取消仍保持未填。打开时间编辑时先收起活动键盘。弹层修改临时副本，应用有效值才回写；取消和系统返回不应用。结束钟点小于开始钟点时，明确让用户选择下一天，不默默推断跨日。任意分钟可选，不能把表盘上5分钟标签误用为只能选5分钟倍数。

系统预填起止均 approximate，手动点击日期 / 表盘不自动变 exact。全应用数值不显示“约”；精度选择仍保留。无效时间不能应用，重开显示上次有效应用值，遵守 Q-024。

**核验依据（2026-10-05）：**

- [showTimePicker](https://api.flutter.dev/flutter/material/showTimePicker.html) / [TimePickerEntryMode](https://api.flutter.dev/flutter/material/TimePickerEntryMode.html)：表盘选时分、可选输入切换与 dialOnly。
- [showDatePicker](https://api.flutter.dev/flutter/material/showDatePicker.html) / [DatePickerEntryMode](https://api.flutter.dev/flutter/material/DatePickerEntryMode.html)：日历选日、calendarOnly。
- [ThemeData.useMaterial3](https://api.flutter.dev/flutter/material/ThemeData/useMaterial3.html)：Material 3 覆盖基础按钮、Chip、分段选择、日期 / 时间选择器等。
- 当前本机 Flutter SDK 源码包含上述 only 模式以及 `SegmentedButton.emptySelectionAllowed`；只核对 API 存在性，未在本任务编译或跑设备。
- 现有 `recording_form.dart` 的大字日期路径会进入 inputOnly，新基线下需要重新验证 / 调整。`activity_time_sheet.dart` 的时钟依赖已有有效日期；新无时间建议入口必须同时提供无键盘选日路径，不能仅复用时钟按钮便认定合格。

## 进一步补充与另一种输入方式

主线严格保持三幕，不因为选卡住 / 休息多出必答问题。第三幕提供一个次级“补充这笔记录”动作，打开与当前状态适用的内容：原因、恢复方式 / 感受、接续点、备注。它是用户主动进入的补充，不在保存后自动展开。接续点三种节奏均可填，与每日复盘的明天第一步不同。

补充内容中不再套多层折叠；应用后回到第三幕，显示已有内容摘要。返回修改第一幕时，保留附属输入，只显示和使用当前状态适用字段。未选择节奏时不产生annotation；已经选择节奏时，无需填写原因、恢复细节或接续点也能保存对应解释。

设置规划为“记录方式：问答引导 / 表单填写”，初版优先问答。两种方式使用相同事实、保存校验与草稿内容，不迁移数据库、不把模式写入领域实体。模式设置是本机 UI 偏好，不能因切换清空未保存内容。建议模式切换从下一次进入记录开始生效，当前编辑不中途改布局；此项属于待验证交互建议。

## 首轮原型验收

1. 有目标：卡住 → 理表关系 → 接受时间 → 保存，目标全程可见。
2. 普通生活：取消本笔目标、不选节奏 → 午饭 → 确认时间 → 保存，常用目标设置不受影响。
3. 无目标：不建目标也能选节奏并完成三幕。
4. 想不起来：第二幕选择 Unknown → 确认时间 → 保存，先前答案不被自动清空。
5. 无时间建议：日期日历 + 小时 / 分钟表盘 + 独立精度，无键盘完成两端。
6. 跨日：明确选择第二天，查看完整区间和时长；取消时间修改还原上次应用值。
7. 回改：第三幕返回第一幕改状态，活动、时间、适用细节和光标内容保留，回到第三幕继续。
8. 退出 / 恢复：恢复同一草稿的答案；引导所处幕作为 UI 状态恢复，不新增领域 draft 状态。
9. 保存冲突 / 保存失败 / 提交后收尾失败：输入不丢，正式结果表达准确。
10. 320/360/412、1/1.5/2倍文字、短窗口 / Android 和 Web：主要动作、日历与表盘可达；不可用强制文本输入来绕过布局问题。

正式实现仍需针对当前 SDK 实测日期 / 时间组件的布局、无障碍与平台输入。HTML 可以验证问答流程，但不能用浏览器原生 datetime-local 或仿制表盘冒充 Flutter MD3 组件验收。
