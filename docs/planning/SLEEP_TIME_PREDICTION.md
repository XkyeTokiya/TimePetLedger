# TIME-04 — 个人睡眠初值与多日空白修复

日期：2026-10-07。状态：本任务范围实现与验证完成。用户报告10月4日晚至7日早被预填为56小时睡眠，随后明确选择“采用推荐模型与参数”。实施来源为Q-036、Q-037本次睡眠决定和[算法设计稿](TIME_RECORDING_AUTOMATION_REVIEW.md)。

## 本轮范围

睡眠新建使用独立模型，不再把整个Gap归为一次睡眠。无历史主睡眠为23:00–次日07:00；个人主睡眠 / 小睡分别学习循环本地时刻与完整时长，保留昼夜多峰。历史从最新已发生同类型睡眠向前56天、最多60条，按实际睡眠日期排序；14天半衰期，断记不会清掉原作息。时刻核90分钟、对数时长核0.25、常规先验量2，手改 / 旧来源未知 / 原样沿用分别1 / 0.5 / 0.1；弱反馈各端总量至多为独立证据20%，没有独立证据不自行强化。无历史小睡最近30分钟，历史日期使用打开时刻的本地时分定位该日期，不另定午睡作息。

默认主睡眠按醒来日期定位。今日优先最近已结束或覆盖当前时刻的个人睡眠；历史 / 未来日以所选醒来日期为焦点。真实占用约束候选，优先用个人完整时长移到真实边界；没有合理完整位置则保留完整估计及原有冲突反馈，不把主睡眠压成几分钟。预测不是正式事实，旧Gap保留，用户可改任意合法日期 / 时长；无固定时长上限。

进入捕获一次时刻、事实和主睡眠 / 小睡初值，直接写编辑缓存。切换类型使用同一快照对应的初值；用户改过端点后不覆盖。正式更正与提交恢复不套新建模型；原子不重叠不变。

## 实施组织与验证

- 纯domain模型接受完整样本、明确时钟和日期适配，不读取设备全局时间 / 数据库；application加载完整历史和真实占用；app提供本地日历适配。
- 学习反馈为按睡眠ID关联的本机辅助信息，使用睡眠草稿专用数据库，保存模型初值、实际提交值和当地UTC offset。它不改SleepSession / 正式数据库schema，不参与账本统计；更正后基于现存事实重算，删除后不再训练。正式提交成功后，反馈写入和清草稿在同一辅助事务，失败沿原提交收尾恢复重试，不重复正式写入。
- 用截图复现、冷启动、昼睡、午夜圆距离、多峰、长期断记、漏睡眠 / 多次睡眠、正式占用、类型切换 / 手调 / 重进、弱反馈与真实SQLite迁移 / 保存 / 恢复检查。
- 格式、静态分析、相关模型 / loader / controller / data / editor回归；保留TIME-03的5小时活动规则和Q-038独立日期时间编辑。

统计模型的工程实现不声称评分已校准或80%已达成。其他活动模型、星期条件 / 模式变化标定、80%误差容差仍未决；本任务不扩展其他能力。
