# Time Pet Ledger｜日账本首页设计文档 v1.0

**设计范围：日账本首页 / Daily Ledger Home**  
**核心改动：真实比例时间轴 + 双态顶部结构 + 更明确的事实状态表达**  
**本文暂不讨论 Rhythm。**

---

# 1. 页面定位

日账本首页不是传统意义上的“今日概览”，也不是日程表。

它承担三个核心任务：

> **看见一天 → 发现尚未解释的时间 → 补全或修正事实。**

因此首页首先是一个**时间事实浏览器**，其次才是统计页和操作入口。

用户打开首页时，应该能够在很短时间内回答：

1. 我现在看的是哪一天？
2. 这一天有多少时间已经被交代？
3. 哪些时间仍然没有记录？
4. 已经发生了哪些事情？
5. 哪些时间是“确实想不起来”，而不是“还没处理”？
6. 我要从哪里继续补记？

整个设计围绕这六个问题展开。

---

# 2. 当前版本存在的问题

当前首页已经形成了比较稳定的视觉气质：

- 温和；
- 克制；
- 类似纸质账本；
- 日期感较强；
- 没有典型 productivity dashboard 的压迫感。

这些应该保留。

真正的问题主要来自**信息结构和时间表达能力不足**。

目前的时间轴实际上更接近：

> 带时间信息的纵向列表。

而不是：

> 一天时间在空间上的映射。

于是会出现：

| 当前问题 | 后果 |
|---|---|
| 40 分钟、1 小时、2 小时视觉高度接近 | 时长主要依靠阅读文字才能理解 |
| 尚未记录与正常记录结构过于相似 | Gap 不够醒目 |
| Unknown 与 Gap 都比较弱 | 两个核心产品概念容易混淆 |
| 日期、统计、列表、提醒、底栏视觉权重接近 | 第一眼漂亮，但扫描效率较低 |
| 顶部永久占用大量空间 | 浏览长时间轴时有效空间不足 |
| 今天没有记录时出现大片视觉空白 | “未交代时间”容易被误读成“没有内容” |

因此本次改版的关键不是换一套视觉风格，而是：

> **让页面真正具有时间结构。**

---

# 3. 核心设计原则

## 3.1 时间首先是一种空间关系

同样的一小时，在时间轴上必须拥有相同的视觉长度。

例如：

```text
20 min      ██

40 min      ████

1 h         ██████

1 h 20 min  ████████

2 h         ████████████
```

用户应该在**不读取“2 小时”文字的情况下**，也能够感受到哪一段更长。

---

## 3.2 事实状态比活动分类更重要

首页第一视觉分类不是：

> 工作 / 吃饭 / 学习 / 娱乐

而是：

```text
已经明确的事实
尚未记录
已经确认想不起来
睡眠
```

这是 Time Pet Ledger 与普通时间管理工具的区别之一。

---

## 3.3 Gap 不是“空白”

`尚未记录` 是一个非常明确的信息状态。

因此：

> 页面上绝对不能通过真正的空白来表达 Gap。

即使今天从 00:00 到 12:12 什么都没有记录，这 12 小时仍然应该作为一个明确的时间块存在。

---

## 3.4 Unknown 不是 Gap

两者必须建立稳定视觉语言：

**尚未记录**

> 用户还没有交代这段时间。

**想不起来**

> 用户已经处理过这段时间，并确认自己无法回忆。

所以：

```text
Gap     = 待处理
Unknown = 已处理的不确定事实
```

用户无需理解领域模型，也应该从界面上自然感知这个区别。

---

## 3.5 首页不是统计 Dashboard

`已交代 / 尚未记录` 很重要，但它只是**整日状态摘要**。

它不能压过真正的主体——时间轴。

所以统计区域保留在上方，但从“大数字展示区”改为：

> **Ledger Status / 账本状态条。**

---

# 4. 页面整体结构

首页分为四层：

```text
┌─────────────────────────┐
│ ① 日期与页面导航          │
│                         │
│        10月7日           │
│       周三 · 昨天         │
├─────────────────────────┤
│ ② 今日账本状态            │
│ 已交代     █████░░ 尚未记录│
├─────────────────────────┤
│                         │
│ ③ 真实比例时间轴           │
│                         │
│ 08:00 ┃ █████████        │
│ 09:00 ┃ █████████        │
│ 10:00 ┃ █████            │
│ ...                     │
│                         │
├─────────────────────────┤
│ ④ 情境提醒                │
│ 刚才在做什么？      补记一笔│
├─────────────────────────┤
│ 记录睡眠        记录一笔   │
└─────────────────────────┘
```

其中：

> **③ 时间轴是页面真正的主体。**

---

# 5. 首页存在两个视觉状态

这是本次设计非常重要的一部分。

不是简单设计一张静态首页，而是设计：

### A. 初始状态

用户刚进入页面时。

特点：

- 日期区域完整展开；
- 星期 / 今天 / 昨天完整显示；
- `回到今天` 明确可见；
- Ledger Status 完整展示；
- “刚才在做什么？”提醒卡存在；
- 时间轴从较低位置开始；
- 强调“这是哪一天”和“目前一天是什么状态”。

这是用户的**定位状态**。

---

### B. 滚动状态

用户开始浏览时间轴。

顶部自动压缩。

例如：

```text
☰ 日账本       ‹ 10月7日 周三 ›
────────────────────────
已交代 16h20m     尚未记录 7h40m
────────────────────────
08:00
09:00
...
```

变化：

| 元素 | 初始状态 | 滚动状态 |
|---|---|---|
| 大日期 | 展开 | 收入标题栏 |
| 星期说明 | 可见 | 合并 |
| 回到今天 | 明确按钮 | 小型按钮/图标 |
| Status | 完整 | 压缩 |
| 提醒卡 | 显示 | 消失 |
| 时间轴 | 页面中部开始 | 获得更大空间 |
| 底部记录按钮 | 固定 | 固定 |

这就是之前生成的两张参考图之间最合理的关系。

---

# 6. 初始顶部设计

## 页面标题

左上：

```text
☰   日账本
```

它表示当前一级模块，而不是一天的信息。

视觉权重低于日期。

---

# 7. 日期导航

建议初始状态采用：

```text
        10月7日
       周三 · 昨天
    ‹             ›
               回到今天
```

也可以把左右箭头与日期放一行。

核心要求：

### 日期必须是主视觉锚点

用户进入首页首先应该知道：

> “我在看哪一天。”

但不必像当前版本一样占据过多垂直空间。

推荐逻辑字号：

```text
日期         40–46sp
星期         15–17sp
页面标题      24–28sp
```

日期是唯一的大标题。

---

# 8. “回到今天”

只有当前日期不是今天时出现。

例如：

```text
回到今天
```

不要永久占据固定布局空间。

当天：

```text
10月8日
周四 · 今天
```

则不显示“回到今天”。

这样可以降低页面噪声。

---

# 9. 已交代 / 尚未记录区域

## 定位

这一块应该回答：

> **这一天目前解释到什么程度了？**

而不是详细解释一天。

---

## 推荐结构

```text
已交代                         尚未记录
16小时20分                     7小时40分

████████████████████░░░░░░░░
```

或者横向：

```text
已交代 16小时20分  █████████░░░  7小时40分 尚未记录
```

初始状态可以稍微舒展。

滚动后压成一行。

---

# 10. 是否应该加入百分比？

不推荐主界面展示：

```text
已完成 68%
```

因为“完成率”很容易把产品带到：

> 今天完成得好不好？

而你的概念实际上是：

> 今天有多少时间已经被解释。

所以：

**时长优先，比例只作为图形辅助。**

---

# 11. Unknown 是否加入顶部统计？

不建议在主状态区增加第三个大指标。

否则：

```text
已记录
未知
尚未记录
```

会增加理解复杂度。

推荐：

> Unknown 仍属于“已交代”。

但用户进入详情时可以看到：

```text
已交代 16h20m

其中：
明确事实    15h
想不起来    1h20m
```

首页保持简单。

---

# 12. 真实比例时间轴

这是整个新版首页的核心。

---

## 12.1 时间比例固定

建议基础比例：

> **1 小时 ≈ 72dp**

即：

```text
1 min = 1.2dp
```

那么：

| 时长 | 几何高度 |
|---|---:|
| 20 min | 24dp |
| 30 min | 36dp |
| 40 min | 48dp |
| 1 h | 72dp |
| 1 h 20m | 96dp |
| 2 h | 144dp |
| 3 h | 216dp |

这已经能比较明显地区分时间长度。

---

# 13. 一个关键问题：20 分钟块太矮怎么办？

这里**不要为了放文字破坏真实比例**。

即：

不能规定：

```text
所有 item 最小高度 64dp
```

否则：

```text
20min ≈ 40min ≈ 1h
```

又会退化成普通列表。

正确方式是：

### 几何高度保持真实比例

但允许：

> **视觉块高度 ≠ 点击热区高度。**

例如 20 分钟块：

```text
实际视觉高度：24dp
隐形点击区域：至少 44–48dp
```

或者点击后展开详情。

---

# 14. 小时间段的内容表达

### ≥ 60 分钟

完整显示：

```text
14:20–16:20                    2小时

毕业设计：修改图表
调整数据与图形，完成初稿
```

### 30–60 分钟

简化：

```text
12:20–13:00       午餐       40分钟
```

### < 30 分钟

单行：

```text
12:00–12:20   ○ 尚未记录   20分钟
```

因此内容密度随空间自动变化。

不要强迫所有块使用相同组件模板。

---

# 15. 左侧时间标尺

推荐结构：

```text
08:00 ── ●
          │
09:00 ── │
          │
10:00 ── ●
```

时间轴承担：

1. 时间位置；
2. 时间连续性；
3. Activity 边界；
4. Gap 边界。

---

# 16. 时间刻度

主刻度：

```text
每 1 小时
```

必要时：

```text
30 分钟弱刻度
```

但不要把每半小时都显示为文字。

否则页面会变得像专业 Calendar。

推荐：

```text
09:00 ─
       ·
10:00 ─
```

---

# 17. 时间轴与内容块必须强绑定

当前版本存在的问题是：

> 左边像时间轴，右边像列表。

新版应该让它们成为一个整体。

推荐：

```text
12:00 ─○────────────┐
      ┆ 尚未记录     │
      ┆              │
12:20 ─●────────────┘
```

内容块左边缘离轴线不能太远。

视觉上让用户感受到：

> 这个块就是从 12:00 延续到 12:20。

---

# 18. 时间块视觉类型

首页建议固定四套核心视觉语言。

---

## 普通 Activity

建议：

- 实体背景；
- 非常轻的填充；
- 左侧强调色边；
- 实心节点。

例如：

```text
●│ 11:00–12:00
 │
 │ 与导师讨论
 │ 毕业设计
```

不建议每种 Activity 都使用不同强颜色。

Activity Category 不是首页的主要视觉维度。

---

# 19. 尚未记录 / Gap

必须有强烈但不压迫的“待处理感”。

建议：

- 无实色填充或极淡背景；
- 虚线边框；
- 空心节点；
- 时间轴使用虚线；
- `尚未记录` 明确出现；
- 提供直接补记 affordance。

例如：

```text
○┆┌ - - - - - - - - - ┐
 ┆│ 尚未记录      20分钟│
 ┆└ - - - - - - - - - ┘
```

它应该一眼表达：

> **这里还有事情没处理。**

---

# 20. Unknown / 想不起来

视觉目标：

> “这是已经交代过的事实，但信息内容未知。”

所以不要用 Gap 的虚线语言。

推荐：

- 实体灰背景；
- 灰色实心节点；
- `?` icon；
- 明确辅助文字：

```text
想不起来
已交代 · 记不清具体做了什么
```

这句话非常重要。

它自然向用户解释：

> Unknown 与尚未记录不是一回事。

---

# 21. Sleep

Sleep 属于事实，但不同于普通 Activity。

推荐：

- 柔和冷色；
- 月亮 / 床图标；
- 独立但低饱和视觉语言；
- 同样严格遵守真实比例。

不要让 Sleep 变成首页视觉焦点。

---

# 22. Goal 信息

Goal 作为 Activity 的第二层信息。

例如：

```text
毕业设计：修改图表
毕业设计
```

其中：

```text
毕业设计：修改图表  = Activity title
毕业设计           = Goal
```

Goal 建议：

- 小字号；
- 弱色；
- 不使用大面积彩色 badge。

因为首页的任务不是分析 Goal。

---

# 23. 当前时间

“今天”页面应该增加：

> **Now Line / 当前时间线**

例如当前是 12:12：

```text
12:00 ──────────────
       尚未记录
12:12 ─────── NOW ───
```

使用一个非常克制的强调色。

意义很大：

用户能够立即理解：

> 我的今天已经发展到这里。

而不是只看到一个 `00:00–12:12 尚未记录`。

---

# 24. 未来时间如何处理

这是非常重要的产品规则。

今天 12:12：

```text
00:00 ───── 12:12
```

属于已经发生的时间。

而：

```text
12:12 ───── 24:00
```

**不是 Gap。**

因为未来还没有发生。

因此时间轴中：

```text
过去未记录 → Gap

未来时间 → 不生成任何账本事实
```

可以轻微淡化显示未来刻度，但不能写：

> 尚未记录 11小时48分

否则产品语义错误。

---

# 25. 提醒卡设计

初始状态保留：

```text
💡 刚才在做什么？
   趁现在还记得，补记一笔吧～

                       补记一笔 ›
```

但这个区域不是账本内容。

所以：

> **开始滚动后消失。**

它是 contextual action，而不是永久导航。

---

# 26. 提醒卡什么时候出现

推荐条件：

### 今天 + 最近存在 Gap

出现：

```text
刚才在做什么？
```

### 历史日期

更适合：

```text
这段时间还记得吗？
```

或直接取消提醒卡。

因此提醒应该与页面上下文有关，而不是固定 banner。

---

# 27. 底部操作栏

固定底部：

```text
┌────────────┐ ┌────────────────┐
│ ◯ 记录睡眠 │ │ ✎ 记录一笔     │
└────────────┘ └────────────────┘
```

`记录一笔` 是主操作。

`记录睡眠` 是次操作。

---

# 28. 为什么保留两个按钮

因为 Sleep 和普通 Activity 在领域上本身就是不同事实类型。

因此首页直接提供两个入口是合理的。

但视觉权重应该明显不同：

```text
记录睡眠 → Outline / secondary
记录一笔 → Filled / primary
```

---

# 29. 滚动行为

设计建议：

### 0–40dp 滚动

仍处于初始形态。

### 40–120dp

开始压缩：

- 大日期缩小；
- 星期并入标题；
- 状态摘要高度减少；
- reminder 开始离开屏幕。

### >120dp

进入完整滚动模式。

顶部变成 sticky：

```text
☰ 日账本     ‹ 10月7日 周三 ›
已交代 16h20m   ▰▰▰▱   尚未记录 7h40m
```

不再恢复大头部，直到滚回顶部。

---

# 30. 滚动时的时间感

当用户滚动到例如 15:00，可以在顶部或者时间轴边缘保留：

```text
15:00
```

作为当前位置提示。

但第一版不必实现复杂 Calendar 式 sticky hour。

---

# 31. 默认滚动位置

这是一个值得设计的细节。

### 今天

默认靠近：

> **当前时间附近。**

例如现在 12:12：

首页初始展示 08:00–当前时间比较合理。

不需要让用户从 00:00 一直往下滚。

### 历史日期

默认：

> 从当天第一条有效事实附近开始。

---

# 32. 完全没有记录的今天

不要出现：

> 巨大空白页面 + 一个尚未记录条目。

应该形成：

```text
已交代 0分钟
尚未记录 12小时12分

00:00
 ┆
 ┆
 │ 尚未记录
 │
 ┆
12:12 ───── 现在
```

整个未记录时间段应该成为真实比例的大块。

这反而能非常强地表达：

> “今天已经过去这么多时间了。”

---

# 33. 一整天都已交代

顶部：

```text
已交代 24小时
尚未记录 0分钟
```

不要出现庆祝动画、奖杯、绿色 Success。

因为：

> 记录完整不是成绩。

可以只是安静地显示：

```text
今天已经全部交代。
```

---

# 34. 用户点击 Gap

点击：

```text
12:00–12:20 尚未记录
```

直接进入：

> 为该区间补记。

时间自动预填：

```text
开始：12:00
结束：12:20
```

这是时间轴最重要的交互之一。

Gap 本身就是入口。

---

# 35. 用户点击 Unknown

进入 Fact Detail。

可以：

```text
修改为具体记录
修改时间
继续保持“想不起来”
删除
```

不要出现：

> “补记”

因为它已经是一个合法事实。

---

# 36. 点击普通 Activity

进入事实详情页。

首页不要塞过多操作。

例如：

```text
与导师讨论
11:00–12:00
Goal：毕业设计
```

点击后再：

```text
编辑
删除
其他属性
```

---

# 37. 横向滑动日期

可以支持：

```text
← 前一天
→ 后一天
```

但不能影响纵向 Timeline 滚动。

如果误触风险明显，可以只保留箭头，不必强行做 swipe。

---

# 38. 视觉设计方向

现有视觉风格建议保留：

```text
暖白背景
砖红主色
低饱和辅助色
细线
大留白
有纸张 / 日记感的中文排版
```

不建议突然转成：

- Material 3 彩色卡片；
- 强渐变；
- 高饱和 Goal 分类；
- Dashboard 风格；
- 大量图标。

---

# 39. 色彩的真正用途

颜色应该优先表达：

> **事实状态**

而不是 Activity Category。

推荐语义：

| 状态 | 视觉倾向 |
|---|---|
| Normal fact | 暖白 / 淡橙 |
| Sleep | 淡蓝灰 |
| Unknown | 中性灰 |
| Gap | 无填充 + 砖红虚线 |
| Current | 主强调色 |
| Future | 极淡灰 |

这样整个页面的视觉语法会稳定得多。

---

# 40. 字体层级

建议控制在五级以内：

| 层级 | 示例 |
|---|---|
| Display | `10月7日` |
| Title | `毕业设计：修改图表` |
| Body | `与导师讨论` |
| Meta | `14:20–16:20` / Goal |
| Caption | 说明与状态 |

不要同时存在太多字号。

---

# 41. 时间文字不要重复过度

真实比例时间轴本身已经表达时间位置。

所以 Activity 内不必每次都重复：

```text
14:20
16:20
```

推荐：

```text
14:20–16:20
```

一行即可。

左侧刻度负责空间定位。

右侧文字负责精确确认。

二者是互补关系。

---

# 42. 可访问性

真实比例布局不能牺牲 accessibility。

每个时间块完整语义，例如：

```text
毕业设计：修改图表。
下午两点二十分至四点二十分。
持续两小时。
关联目标：毕业设计。
```

Gap：

```text
尚未记录。
中午十二点至十二点二十分。
持续二十分钟。
双击补记。
```

Unknown：

```text
想不起来。
下午一点至两点二十分。
持续一小时二十分钟。
这段时间已经交代。
```

这里尤其要让辅助技术理解：

> Gap 与 Unknown 的差异。

---

# 43. 小屏幕策略

320dp 宽度时，不改变整体信息架构。

优先压缩：

1. Activity subtitle；
2. icon；
3. 右侧 duration；

不能压缩：

- 时间轴；
- 时间范围；
- Activity title；
- Gap / Unknown 状态。

例如窄屏可以：

```text
14:20–16:20
毕业设计：修改图表
2h
```

---

# 44. 横屏策略

横屏不要简单把纵向页面压矮。

可以：

```text
左侧 25–30%
日期 + 状态

右侧 70–75%
时间轴
```

但这可以作为后续迭代。

第一版本重点仍然是竖屏。

---

# 45. 动效

保持克制。

推荐只有三类：

### Header collapse

约：

```text
180–240ms
```

### 新增记录

Gap：

```text
虚线块
   ↓
淡入实际 Fact block
```

这是一个很有意义的变化。

### 日期切换

轻微横向位移 + fade。

不要用弹跳、庆祝或粒子效果。

---

# 46. 页面加载

如果数据读取很快：

不显示 Skeleton。

如果超过约 200–300ms，可显示：

- 顶部固定；
- 时间轴轻量占位。

不要让整个页面大面积灰块闪烁。

---

# 47. 设计中应避免的方向

本次设计明确不做：

- Calendar 式复杂日程管理；
- 可拖拽安排未来；
- 时间效率评分；
- Goal 饼图塞入首页；
- Rhythm 在首页占据主视觉；
- Activity Category 彩虹配色；
- 强迫每条记录有 icon；
- 用固定高度卡片代替真实时间比例。

---

# 48. 新旧首页最核心的差异

旧：

> **时间信息存在于每个 item 的文字中。**

新：

> **页面本身就是时间。**

旧页面需要用户阅读：

```text
1小时
40分钟
1小时20分
2小时
```

才能理解时间关系。

新版即使模糊掉所有文字，用户仍然能从页面形状看见：

> 哪些时间长、哪些时间短、哪里断掉了、哪里尚未交代。

这是此次改版成功与否最重要的判断标准。

---

# 49. 页面最终信息优先级

从高到低应该是：

```text
① 我在看哪一天

② 这一天发生了什么
   ↓
   时间轴

③ 哪些时间还没有被解释

④ 这一天整体已经交代多少

⑤ 我现在可以做什么
```

这里有一个看似矛盾但很重要的点：

**视觉顺序**可以是：

```text
日期
状态
时间轴
操作
```

但**用户注意力的核心**应该最终落在时间轴上。

所以状态区域虽然在时间轴上方，却不能比时间轴更抢眼。

# 51. 验收标准

这个改版最终不应该以“是不是更漂亮”判断。

应该用下面几个问题验收：

| 测试 | 成功标准 |
|---|---|
| 不看时长文字能否分辨 40min / 2h | 能 |
| 一眼能否找到尚未记录时间 | 能 |
| 一眼能否区别 Gap / Unknown | 能 |
| 今天未记录很多时是否会误以为页面没内容 | 不会 |
| 是否立即知道当前看哪一天 | 是 |
| 顶部是否压过时间轴 | 否 |
| 长时间浏览时顶部是否浪费空间 | 否 |
| 点击 Gap 是否可以直接处理该时间 | 是 |
| Future 是否会被错误计算成 Gap | 否 |
| 首页是否仍保持安静、不评价用户 | 是 |

# 52. 最终设计判断

我认为这个首页最重要的一次转变应该是：

> **从“纵向排列的记录列表”，转向“可以阅读的一天”。**

真实比例时间轴并不仅仅是视觉变化。

它实际上强化了 Time Pet Ledger 最底层的产品思想：

> 时间不是任务集合。  
> 它是一段连续发生的现实。

Activity、Sleep、Unknown 和 Gap，都只是在这条连续时间上留下不同性质的事实。

所以首页最终不应该让用户感觉：

> “这里有六条记录。”

而应该让她感觉：

> **“这就是我的这一天。”**

这也是我认为这次首页重设计最值得坚持的核心。
