# TIME-03 — 长Gap后的活动新建初值

日期：2026-10-07。状态：本任务范围实现与验证完成，实际证据见末尾交付报告。用户在确认5小时 / 60分钟规则后明确要求“请你着手开始实现”。依据：[源提案后续决定](../../time-ledger-domain-model-v4-proposal.md)、[Q-037部分决定](../domain/OPEN_QUESTIONS.md#q-037)及[时间建议合同](../domain/DOMAIN_RULES.md)。

## 范围与规则

当前日普通活动新建，令t₀为本次打开时刻。实际主要事实之后至t₀的尾部连续Gap达到5小时（含边界），直接给`[t₀−60分钟,t₀)`，无需选择；不足5小时保留TIME-01现行行为。判定用完整毫秒与跨日相邻事实，不使用首页已按自然日裁剪的Gap长度。TimeBlock（包括Unknown）、主睡眠及小睡均中断空白；无前序事实只计算当前已知对账窗口。

进入即使用该初值替换旧草稿端点，保留事项 / 备注等内容；同次编辑稳定，重新进入重算。初值仍可手动修改任意合法端点，60分钟不构成时长限制。初始化不写正式事实，提交一笔后其余时间继续为派生Gap，不自动生成Unknown或睡眠。

不扩用到显式Gap补记、睡眠入口、历史 / 未来日、正式更正或已提交草稿收尾恢复。不修改Q-038独立日期 / 时分交互，不新增字段、数据库迁移、依赖、提醒、进行中状态或其他任务。Q-037其余睡眠学习与活动模型参数仍未决。

## 实施与验收

1. 在完整事实初始化函数中，先检查当前正式占用，再判断普通活动长尾分支；复用现有跨日repository查询和控制器缓存接线。
2. 真实SQLite测试覆盖恰好5小时、前后1毫秒、跨午夜、多日断记、无前序事实，以及四种主要事实中断空白。
3. 验证显式Gap / 睡眠 / 历史 / 未来入口不受该分支影响，未来已占用区间不会被近期初值包含。
4. 贯通初始化、缓存、手调、重复初始化、新会话重算、正式提交、清草稿及当日 / 历史剩余Gap；回归正式更正与提交收尾恢复。
5. 本次Dart格式 / 格式检查、全仓库静态分析、相关应用 / 控制器 / 查询测试；文档链接与diff检查。未修改UI或平台适配，本任务不重新宣称TIME-01 / TIME-02整个平台验收完成。
